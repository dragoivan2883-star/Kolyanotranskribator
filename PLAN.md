# План MVP: локальный транскрибатор для Windows

## Цель

Сделать как можно быстрее **работающую первую версию** приложения для локальной транскрибации аудио и видео в текст. Без браузера, без интернета при обычной работе, без платных API и без встроенного редактирования текста.

> Статус: требования к разработке, не отчёт о уже реализованных функциях.

## Технологии

- **C# + WPF** — отдельное окно Windows.
- **whisper.cpp** на CPU с многоязычной моделью **Whisper small** — распознавание речи на языке записи.
- **FFmpeg** — извлечение звука из видео и приведение аудио к подходящему формату.
- Цель поставки: переносимая сборка, включающая необходимые компоненты (.NET, whisper.cpp, модель и FFmpeg). Пока сборка не проверена, не считать приложение готовым к запуску без настройки.

Исходный план основывался на ноутбуке с Ryzen 7 PRO 8845HS, Radeon 780M и ~28 ГиБ оперативной памяти. Скорость распознавания на нём **не измерена**; сначала проверить минутный русский аудиофайл.

## Две рабочие папки

Рядом с исполняемым файлом (либо в другом заранее выбранном рабочем каталоге) приложение создаёт:

```text
Kolyanotranskribator/
├── Входящие/
└── Исходящие/
```

- **Входящие:** пользователь кладёт аудио- и видеофайлы на обработку.
- **Исходящие:** после успешной транскрибации приложение сохраняет `.txt` с тем же базовым именем и **перемещает туда исходный медиафайл**. То есть успешная обработка не оставляет файл во «Входящих» для повторного запуска.
- **Ошибка обработки:** исходный файл остаётся во «Входящих», пользователь видит понятное сообщение.
- Если такое имя уже есть в «Исходящих», не перезаписывать существующие файлы: подобрать свободное имя для пары «исходник + текст».

Пример:

```text
Входящие/
└── Встреча.mp4

# После успешной обработки:
Исходящие/
├── Встреча.mp4
└── Встреча.txt
```

## Минимальный интерфейс

Одно светлое окно на русском языке:

1. Кнопки **«Открыть Входящие»** и **«Открыть Исходящие»**.
2. Кнопка **«Обработать входящие»** (обработка файлов по одному, без сложного интерфейса очереди).
3. Строка состояния: какой файл сейчас обрабатывается и результат.
4. Понятное сообщение об ошибке без технической «простыни»; подробности можно выводить в диагностический лог при необходимости.

Перетаскивание файла в окно и кнопку «Выбрать файл» можно добавить после запуска основного сценария. Это не должно блокировать готовность первой версии.

**Не требуется:** встроенный редактор транскрипции, просмотр текста в приложении, копирование из интерфейса, история, таймкоды, разделение по спикерам, сложные настройки, полноценное управление очередью и отмена.

## Сценарий обработки

1. При запуске создать «Входящие» и «Исходящие», если их нет.
2. Пользователь кладёт запись во «Входящие» и нажимает «Обработать входящие».
3. Приложение последовательно обрабатывает доступные поддерживаемые файлы по одному, не замораживая окно.
4. FFmpeg готовит временное аудио; whisper.cpp распознаёт речь (язык определяется автоматически).
5. Записать текст в UTF-8 `.txt`; при успехе поместить в «Исходящие» текст и оригинал. Не удалять оригинал.
6. **Всегда** очищать временные файлы, включая ошибки FFmpeg, распознавания и сохранения.
7. При ошибке сообщить, что именно не удалось, оставить исходник во «Входящих» и перейти к следующему файлу.

Не удалять и не перемещать исходник при неуспешной транскрибации. Не считать пустой результат успешным, если распознавание не дало текста без объяснимой причины.

## Минимальные проверки

- Русская аудиозапись около минуты: получаем осмысленный `.txt`.
- MP4 с кириллицей и пробелами в имени: получаем `.txt` и исходник в «Исходящих».
- Проверка, что существующие одноимённые файлы не перезаписываются.
- Ошибка на файле без звука или повреждённом файле: понятное сообщение, оригинал остаётся на месте.
- Временные аудиофайлы удалены после успеха и ошибки.
- Окно не зависает, текст сохраняется в UTF-8; измерена фактическая скорость на ноутбуке.
